VisualVault, or vivi for short

Your Vault,
without the browser.

An interactive terminal browser for HashiCorp Vault: KV v1 and v2 secrets, policies and auth methods. Values stay masked until you ask, and every write asks first, as loudly as the damage it can do.

The shape of a session

Point it at a Vault.
Read what is there.

  1. Connect like the CLI. VAULT_ADDR and VAULT_TOKEN, or vault login. The token also needs read on sys/mounts, which tells a v1 mount from a v2 one.
  2. Walk a lazy tree. The mounts first, and a path read the first time you open it, so ten thousand secrets start instantly.
  3. Reveal or copy. r shows one field until you move away; y copies it without ever drawing it.
  4. Write with a net. Every KV v2 save carries the version you opened, so a concurrent write is rejected instead of clobbered.
shell
export VAULT_ADDR=https://vault.corp:8200
export VAULT_TOKEN=...        # or: vault login
export VAULT_NAMESPACE=...    # Vault Enterprise only

vivi                          # browse
vivi --read-only=prod         # refuse writes on PROD
Four tabs

One tab for each question you bring to a Vault.

Each recording is a real session against the seeded throwaway Vault that make vault-up starts.

secrets

The lazy tree, masked values, four versions with a diff between two, and a KV v1 mount.

policies

The HCL that decides what a token may do, copied whole or reached by name with :policy.

auth

The enabled methods, the roles under them, and a jump from a grant to the policy it names.

activity

Every write this session made: the operation, its result, its error. Never a secret's content.

Safety

Confirmation scales with the damage.

  1. A save asks y/n. So does a soft-delete, which Vault can undo.
  2. What cannot be undone, you type out. Destroy, deleting the metadata, and any delete on a KV v1 mount.
  3. Rollback destroys nothing. It writes the old content as a new version, and the modal says so.
  4. A session can refuse every write. --read-only everywhere, or --read-only=prod only where the badge says PROD.

What is in the box

The parts of the web UI you actually use.

One binary, no runtime, and no state of its own on disk. Linux, macOS and Windows are built and tested on every change.

├ Lazy tree

Opening it lists the mounts and nothing else. A path is read the first time you expand it.

• Masked by default

Values render as dots until r, and the reveal is dropped the moment you navigate away.

✎ In-panel editing

A form that shows the JSON it will write. A field keeps the type the server gave it, and a pasted certificate keeps its lines.

↺ Version history

Read any version, diff two, roll back, soft-delete, undelete, destroy, or delete the metadata.

⌕ Auditing

Policies and auth methods, read-only. Every secret says what your token may do there, and which of your policies grants it.

⊘ Honest about denial

A path your token cannot list is shown as locked, never hidden. A browser that omits it is worthless for an audit.

⚑ Knows where it is

The header badges the environment, names the server version, warns on a standby or sealed node, and counts the token down.

▤ KV v1 and v2

v1 mounts degrade the interface instead of breaking it: no history, no rollback, and a delete that warns it is final.

␛ Safe to draw

A secret is text someone else wrote. Escape sequences and bidirectional overrides are shown, never run.

: A command line too

: lists what can run right now, with the key beside each entry, so the slow path teaches the fast one.

⎘ Command Reference

The address under the cursor and the vault commands that reach it, one click or one :copy- away.

⇣ Self-update

vivi self-update installs the latest release, checked against its published checksum. No checksum, no install.

Arrows move. Letters act.
